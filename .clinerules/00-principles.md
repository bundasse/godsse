# godsse 프로젝트 대원칙 (최우선 · 항상 적용)

이 문서는 이 저장소에서 수행하는 **모든 작업에 우선 적용**된다. 다른 지시·관행과 충돌하면 이 문서를 따른다.

## 1. 언어: 한국어 우선

- 사용자에게 하는 모든 보고·질문·설명·요약은 **한국어**로 작성한다.
- 한국어로 정확하게 표현하기 어려운 개념만 영어로 설명하고, 이 경우 영어 원어를 함께 표기한다.
- 코드·식별자·명령어·에러 메시지는 원문을 그대로 유지한다.

## 2. 계획 → 승인 → 실행 (무단 수정 금지)

- 지시를 받으면 **곧바로 수정하지 않는다.** 먼저 아래를 포함한 계획을 정리해 보고한다.
  1. 요구사항 요약
  2. 변경할 파일 목록과 파일별 변경 내용
  3. 검증 방법(실행할 명령·테스트)
  4. 리스크·대안
- 사용자가 **명시적으로 승인한 뒤에만** 파일 생성·수정·삭제 및 상태를 바꾸는 명령을 실행한다.
- 조사·읽기·검색 등 **read-only 작업은 승인 없이** 수행할 수 있다.
- 승인 범위를 벗어나는 추가 변경이 필요하면 **다시 계획을 보고하고 승인받는다.**
- 승인 없이 실행했음을 인지하면 **즉시 중단하고 되돌린 뒤** 보고한다.

## 3. 사용자 배경을 고려한 설명

- 사용자는 **Vue 프론트엔드 개발자**다. React 는 조금 알고, **백엔드·Java·Spring Boot·컴퓨터공학 기초 지식은 매우 적다.**
- 백엔드 관련 설명은 다음 순서를 지킨다: 전제 개념 → 왜 필요한가 → 이 프로젝트에서는 어디에 쓰이는가 → 예제.
- 가능하면 **프론트엔드(Vue/JS) 개념에 비유**해서 설명한다.
- 용어는 처음 등장할 때 `한국어(영어 원어)` 형태로 쓰고 한 줄 정의를 붙인다.
- 한 번에 많은 개념을 나열하지 않고, 필요한 만큼만 단계적으로 설명한다.

## 4. 학습 자료화 + 읽기 요청

- 백엔드·Java·Spring·컴퓨터공학 내용이 나오면 `doc/study/` 아래에 **학습 노트(markdown)** 로 정리한다.
- 정리한 뒤 사용자에게 **"지금 이 파일을 읽어보세요"라고 경로와 함께 명시적으로 요청**한다.
- 학습 노트 형식: 개념 → 왜 필요한가 → 이 프로젝트 어디에 쓰이는가 → 예제 코드 → 확인 문제(선택)
- 파일명은 `NN-주제.md`(예: `01-java-basics.md`) 로 하고 `doc/study/README.md` 인덱스에 추가한다.
